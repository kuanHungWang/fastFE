The background of the scenario:

Abstract Node Type:
An abstract node type is a node type that cannot be executed directly just like a abstract class in python.
It defines the interface for a node type. An example:

Abstract Node Type: ScheduleCreator: 
   a node type that create a schedule
Concrete node type of ScheduleCreator:
1. PeriodicScheduleCreator
   create a schedule with start date, end date, and frequency
   in-node parameter: start date, end date, frequency
2. ShiftScheduleCreator
   create a schedule with a base schedule and a shift period
   input node: another schedule
   in-node parameter: shift period
3. MergeScheduleCreator
   merge multiple schedules into one schedule
   input node: ScheduleCreator 1, ScheduleCreator 2, ...
4. ManualScheduleCreator
   create a schedule with a list of dates selected by user
   in-node parameter: list of dates
5. CustomizedCodeScheduleCreator
   create a schedule with a customized code
   in-node parameter: customized code

Template:
A template is a special case of a graph, with part of its nodes are abstract node type.
It serve as a blueprint for creating graph so user don't start from scratch.
It cannot run until user fill in the abstract node type into concrete node type.
A abstract node can appear in the UI with a dot line frame, with a plus sign in the middle.
When user click on the abstract node, a list of available concrete node type will pop up.

Here is the scenario:

User start from a simple template:
ScheduleCreator ----> Model

case 1:
User click ScheduleCreator, then select PeriodicScheduleCreator, then fill in the input, then click save, then click run.

case 2:
User click ScheduleCreator, then select ShiftScheduleCreator, then drag the input node to blank space of the canvas, then a list of available node(all node that output a schedule) pop up, 
then user select PeriodicScheduleCreator, then fill in the input, then click save, then click run.
